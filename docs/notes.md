- `raw/faq.xlsx`：総務省公開のGovbot FAQデータ（令和8年11月19日時点、取得元 https://www.soumu.go.jp/main_content/001102261.xlsx ）
- `out/faq_clean.jsonl`：整形済み4,413件（検索に載せるのは `Z-zz-999` を除く4,412件）。1行1FAQ。`id / alias_ids / area / question / answer / answer_plain / links / urls / as_of / embed_text / sha`
- `out/stats.json`：棚卸し結果（分野別件数など）
- `out/testset_answerable_seed.jsonl`：答えられる質問200問の種（分野比例抽出、seed=20261126）。`user_question` が未記入

- `scripts/build.py`：xlsx → 上記の生成。`scripts/pilot.py`：キーワード検索ベースラインの計測

## 棚卸しで分かったこと
- xlsxは9,819行だが5,203行は空行。実FAQ 4,616問、問い・回答が完全一致の重複203組を統合して4,413件
- 出典URLの列はない。回答文中に `<表示名,URL>` 形式で埋まっている（1,795件）。`links` に分解済み
- 「マイナンバー総合フリーダイヤル」だけ同じ問いで回答が2種類ある
- 埋め込み対象は合計約95万字。1,500字超は2件だけなので1FAQ=1チャンクでよい
- 文字n-gramのキーワード検索（TF-IDF）では、話し言葉30問で上位1件 11/30、上位5件 20/30。意味検索が必要な根拠

- `Z-zz-999`（「この中にはない」）は選択肢で FAQ ではない。検索の索引から外す
- 回答がリンクや「下記をご参照」だけの FAQ（A002・A003・A019 の正解など）と、窓口への案内だけの FAQ は引用が弱い。生成ではなく原文＋リンク表示に回す候補

## 決定済みの設計
1. 検索：埋め込み（bge-m3）だけ。上位5件を再ランク（キーワード併用は計測で下がったのでやめた・`docs/design.md`）
2. 回答可否ゲート：検索スコアと「このFAQで答えられるか」判定を通らなければ生成しない
3. 抜粋ベース生成：モデルは「FAQ IDと引用文」を出力し、引用文が原文に一字一句あるかコードで照合。自由記述は冒頭の要約1文のみ
4. 数値・日付・金額は引用元原文との機械照合。不一致なら回答を破棄
5. URLは生成させず、`links` からコードで差し込む
6. 別モデルで要約文と引用元の矛盾を検証。不合格ならFAQ原文表示に切り替え
7. 質問ログと1回答あたり費用を最初から記録

## 評価（合格ライン）
- テスト300問：答えられる200／FAQにない60／意地悪40
- 誤答（引用元にない内容）0件、正答率85%以上、正しく答えなかった率95%以上、上位5件ヒット率95%以上
- 採点は主張単位。別モデルで照合し、不合格全件と合格の1割を人が確認
- 公式Govbotとの比較は同じ300問で「上位3件に正解FAQが出るか」
- 「FAQにない」確認済みの例（問いに該当なし）：確定申告の一般的な締め切り、自動車税の支払い期限、粗大ごみの出し方
- 境界例（関連FAQはあるが直接は答えていない）：失業保険の受給開始、生活保護の申請、NHK受信料の免除、婚姻届の必要書類、国保保険料の具体額
